# تسليم تجربة صاحبة الصالون — Lena Beauty

## رابط التجربة

- الرابط العام المخصص للتجربة بعد دمج PR هذه المرحلة:
  **https://lenabeauty.vercel.app/#/login**
- Preview الخاص بالـPR محمي بتسجيل Vercel، لذلك لا يُرسل لصاحبة الصالون.
- حساب إدارة Demo موجود، وتُسلَّم بياناته عبر قناة خاصة منفصلة فقط. لا يحتوي
  هذا الدليل على أي قيمة لبيانات الدخول أو الأسرار.

## مسار مقترح — 10 دقائق

1. **دقيقة 1:** تسجيل الدخول، فتح Dashboard، والتأكد أن الواجهة عربية و`RTL`.
2. **دقيقتان:** العملاء → إنشاء عميلة باسم يحمل بادئة واضحة مثل
   `قبول-20260810`، ثم تعديل الهاتف أو الملاحظات.
3. **دقيقتان:** المواعيد → إنشاء موعد للعميلة مع خدمة وموظفة؛ افتحيه ثم
   اختاري «إتمام الموعد» أو «إلغاء الموعد». الحالات النهائية لا تُعدّل بعدها.
4. **دقيقتان:** نقطة البيع → بيع خدمة بسعر ثابت، ثم خدمة يظهر سعرها
   **«يبدأ من»** مع إدخال السعر النهائي المتفق عليه (لا يقل عن الحد الأدنى).
5. **دقيقة:** قبل بيع منتج مخزني سجّلي كميته، أكملي الدفع، ثم تحققي من الكمية
   المحدّثة في نقطة البيع أو المخزون.
6. **دقيقتان:** راجعي الإيصال، ثم التقارير → المبيعات → تفاصيل العملية، وارجعي
   إلى Dashboard للتأكد من ظهور أثر البيع. أعيدي الخطوات الأساسية بعرض جوال.

> كل عملية دفع تُترك في السجل كأثر قبول قابل للتتبع؛ لا تُنشأ فاتورة صورية
> مباشرة في قاعدة البيانات ولا تُحذف فاتورة مدفوعة لإخفاء نتيجة الاختبار.

## ما الذي يُعد بيانات Demo؟

- قاعدة Supabase الحالية بالكامل بيئة **Demo/Acceptance** وليست Production.
- كتالوج العرض المعتمد يحتوي بالضبط على **31 خدمة** ضمن **6 فئات**. لم تضف
  هذه المرحلة خدمات أو فئات أو باقات أو أسعارًا جديدة.
- خدمات `STARTING_FROM` تبقى ظاهرة بصيغة **«يبدأ من»**، ويُطلب سعر نهائي عند
  البيع؛ الحد الموجود ليس اعتمادًا نهائيًا من صاحبة الصالون.
- العملاء والموظفون والمواعيد والمنتجات والمخزون والفواتير والمدفوعات الحالية
  بيانات قبول فقط. أي فاتورة/دفعة/خصم مخزون جديد ينتج من رحلة دفع فعلية داخل
  التطبيق، وليس من seed معاملات مختلقة.
- لم تطبق هذه المرحلة seed لعملاء أو موظفين أو منتجات أو مواعيد أو معاملات،
  ولم تدخل أي بيانات Production.

## بوابة داخلية قبل إرسال الرابط

- تطبيق migration الإضافية
  `20260810000003_appointment_overlap_integrity.sql` على **Demo فقط**، ثم تشغيل
  `supabase/tests/20260810000003_appointment_overlap_integrity.sql`. لا تُطبّق
  على Production في هذه المرحلة.
- تدوير كلمة مرور حساب Demo قبل التسليم الخارجي إذا سبق تداولها في قناة غير
  مخصصة للأسرار، وإرسالها للمالكة عبر مدير كلمات مرور أو قناة خاصة منفصلة.
- تنفيذ قبول حي أخير من الرابط العام: دخول، عميل، موعد، خدمتان، منتج، إيصال،
  تقرير وDashboard. لا تعتمد Preview المحمي بـVercel كتجربة للعميلة.

## قرارات مطلوبة من صاحبة الصالون قبل البيانات الحقيقية

1. اعتماد أسعار الخدمات الـ31 وتحديد ما يبقى «يبدأ من» وما له سعر ثابت؛ لا
   نحول أي حد أدنى إلى سعر نهائي تخميني.
2. اعتماد أسماء الموظفات، الأدوار، الرواتب ونِسَب العمولة.
3. اعتماد قائمة المنتجات الفعلية، تكلفة وسعر كل منتج، الكمية الافتتاحية، وحد
   إعادة الطلب، وهل المنتج يخضع لتتبع المخزون.
4. اعتماد بيانات المنشأة على الإيصال، نسبة الضريبة، وطرق الدفع المستخدمة.
5. بعد الاعتماد: أرشفة/إزالة بيانات القبول وفق خطة متفق عليها قبل إدخال أول
   سجل حقيقي؛ لا تُخلط بيانات Demo مع بيانات الصالون الفعلية.
